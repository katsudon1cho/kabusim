### 4-1. 8/15 に自分で設定した検定は 0/3 でした。結果を都合よく読まないために書きます

## 5. 運用者への報告

### 5-1. 配当の取りこぼしは確定し、次（8/26 SPGI $12.61）も同じ経路で落ちます

**今朝の時点で `受取配当` は両ブックとも $0 / ¥0、`state.json` の `div_through` は両ブックとも `2026-08-18` に進んでいます。**
`_dividends_since()` は `d > since` の**厳密不等号**（`broker.py:336`）なので、
**権利落ち 8/14 の LLY $5.19（$1.73 × 3株）は、今後どの実行でも二度と拾われません。**

現金の増加も突き合わせ済みです。米国株ブックは 8/15 → 8/18 で **+$8.86 = $29,143.8 × 3.70% ÷ 365 × 3日** と
**利息だけで完全に一致**し、配当は1円も入っていません。

**構造は `accrue()`（`broker.py:343-400`）にあります。**

- `now()` が JST なので `today` は JST の日付
- 権利落ち日 D に JST 早朝のセッションが走ると、`since = D-1` で D の配当を探しに行く
- **その時刻は ET の前日夕方で、yfinance の配当系列にはまだ D の配当が載っていない**
- それでも `ok` が真なら **`div_through` は D に進む**（`broker.py:399`）
- 以後 `d > D` になり、**D の配当は永久に対象外**

**8/26 の SPGI（$0.97 × 13株 = $12.61）は、8/26 の JST 早朝にセッションが走れば同じ経路で落ちます。**
AMT の四半期配当（約$52）も同様です。

**そして同じ `d > since` は、ベンチマーク側（`broker.py:388`）にもあります。**
SPY は四半期配当なので、**9月の権利落ちではベンチ側が落ちる可能性があります。**
つまり誤差は一方向とは限らず、**保有側とベンチ側のどちらが落ちるかで比較の歪む向きが変わります。**
CLAUDE.md の「両方に入れないと不公平になる」という設計意図に対して、実装が確率的にどちらかを落とす状態です。

**CLAUDE.md に従い `state.json` は触りません。運用者の判断が要る箇所として4回目の再掲です。**

### 5-2. 保有5銘柄すべてが「撤退未設定」で、設定する手段がありません

`broker.py --help` を確認しました。サブコマンドは
`init / status / quote / history / screen / buy / sell / journal / snapshot / universe / clock` のみで、
**`--stop` は `buy` の引数だけ。既存保有に撤退線を後付けするコマンドが存在しません。**

**対象は米国株4銘柄（総資産の42%）と日本株 6501（同11.2%）で、いずれも `--stop` 必須化（8/14）より前の約定です。**
**「撤退線を割ったら `status` に明示される」という安全装置が、投資済み分の全額に対して効いていません。**
売り切るまで永久に撤退線なしの状態です。**回避策は探しません**（CLAUDE.md の指示どおり）。
